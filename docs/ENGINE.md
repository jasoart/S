# 引擎與原系統修正

版本：2.0.0，2026-10-30。

## 已修正的原始行為

| 原程式問題 | 新行為 |
| --- | --- |
| `minimumTarget` 高於增量上限，低跑量會被迫加量 | 以基準與保守係數計算，不以固定最小里程墊高 |
| 黃／紅燈取消品質課時仍沿用原輕鬆日分母，週總量不一致 | 用整數 0.1 km 分配；每一日相加等於週目標 |
| 紅燈今日寫恢復，週課表仍排跑步、肌力 | 警訊或嚴重恢復不足時整週暫停，重新評估後才重算 |
| 品質課文字的最小公里數與計算值不同 | 課程、週卡、分享及行事曆共用同一份計算結果 |
| 顯示固定 80/20，與實際安排脫節 | 依排入課程的估算分鐘分布，明確區分實測與計畫 |
| 直接用 `220-age` 當成準確區間 | 提供年齡估式／實測輸入，標明誤差與心率受影響的情況 |
| 用睡眠／疼痛推論沒有 REDs 風險 | 不診斷也不排除 REDs，只給適當教育與求助訊息 |
| `Object.assign` 接受任意儲存內容 | 白名單、型別、枚舉與有限數值檢查；舊版欄位遷移 |
| 寫入失敗仍可能卡住 UI | 明確錯誤與備份退路，不宣稱已儲存 |
| 參照未附上的 manifest／圖示／service worker | 補齊全部本機資產與相對路徑離線快取 |

## 設計規則

`assets/js/engine.js` 為無 DOM、無網路、無儲存依賴的純計算模組。

1. 先將參數正規化。基準是近約四週平均週量與近三十天最長跑，並非從少數日誌自動推斷完整訓練史。
2. 急性警訊、發燒、步態改變、疼痛 ≥4，或嚴重恢復不足會停止跑步與肌力輸出。任何程度的惡化都可要求停止；數值閾值不是醫療安全界線。
3. 新手／回鍋預設維持週量；穩定／進階最多乘 1.03。保守或賽前維持模型不加量。黃燈最多乘 0.8。最後兩週／一週最多乘 0.8／0.6。數值均為產品的保守設計。
4. 所有跑步日共同參照相同的三十天基準，單次最多乘 1.05；不以本週上一堂的新距離繼續複利加長。每次另限制在 35 km 以內。
5. 若可跑天數無法容納週量，降低總量。使用整數十分之一公里先平均分配，再於單次上限內調整最長日，不製造額外里程。
6. 最多一堂品質課，只有恢復良好、至少三天、非新手／回鍋、有足夠課程時間、非熱濕時才安排。所有課程暖身／主段／收操分鐘之和等於課程分鐘。距離或時間先到即開始結束，不為湊數加速。
7. 未提供可靠 5K 成績時，時間一律以 8:00/km 作排程估算並標示；不輸出假精確配速。近期成績也不構成乳酸閾值測定。
8. 低／中／高三區是課程主段的時間估計；五個最大心率百分比分帶只作示意，兩者不等同。

## 儲存與隱私

- 新鍵：`pacer-iq-v2`；schema 2 包含 `profile`、`logs`、`updatedAt`。
- 舊鍵 `pacer-iq-coach-state` 可讀取遷移，保留舊值；讀取損壞資料時不自動覆寫，使用者仍可先備份。
- 最多 2,000 筆日誌、匯入上限 2 MB、備註 240 字。匯入整份驗證成功、使用者確認且儲存成功後才替換記憶體內容。
- 日誌備註以 HTML 跳脫呈現。日期使用本機日曆日期，七天窗口採日序計算，不以 UTC 日期字串截斷造成跨日誤差。
- 汗率輸入體重只用於當次計算，不存入資料庫；程式不送出個人訓練資料。
- 讀取其他分頁的變更事件後暫停自動儲存，防止靜默覆寫。單一分頁為主要使用方式。

## 沒有實作的項目

這個版本不預測受傷、賽事完成時間或診斷疾病，不做完整多週週期化，沒有自動 GPS／心率／HealthKit 匯入，也沒有伺服器或多裝置同步。新增這些項目前需另行設計資料與平台整合。
